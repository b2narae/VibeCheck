# VibeCheck 🐎

**프롬프트를 던지고 딴 일을 하세요. 동물이 멈추면 AI가 끝난 겁니다.**

익숙한 루프가 있습니다. 프롬프트를 칩니다. 탭을 옮깁니다. 10초 뒤에 돌아옵니다 —
아직 돌고 있습니다. 다시 옮깁니다. 다시 봅니다. 아직입니다. 결국 감시하지 않으려고
맡긴 일을 감시하고 앉아 있게 됩니다.

VibeCheck은 **코딩 AI가 실제로 일하고 있는 동안에만** 화면 위를 달리는 작은 픽셀 동물을
띄웁니다. 이제 흘깃 보면 됩니다. 아직 달린다? 아직 일하는 중입니다. 멈췄다? 가서 보면
됩니다. 제품은 이게 전부입니다.

![러너들](docs/runners.png)

```bash
git clone https://github.com/b2narae/VibeCheck.git && cd VibeCheck
./scripts/make-app.sh && cp -R build/VibeCheck.app /Applications/ && open /Applications/VibeCheck.app
```

끝입니다. 설정 파일도, API 키도, 로그인도 없습니다. 세션은 알아서 찾습니다.
**Claude Code**, **Codex CLI**, **Gemini CLI** 를 지원합니다.

## 실제로 얻는 것

**🐎 터미널 하나에 동물 한 마리.** 세션을 세 개 돌리면 동물이 세 마리 — 말, 거북이,
작은 공룡 — 각자 특정 터미널에 묶입니다. "다섯 탭 중에 어느 게 아직 돌고 있지?"가
탭을 뒤지는 대신 보면 답이 나오는 질문이 됩니다.

**🧱 벽이 서 있으면 나를 기다리는 중입니다.** Claude가 권한을 묻거나, API 키를
요구하거나, 질문을 던질 때 — 그리고 Codex가 명령 승인을 물을 때 — 그 동물 앞에 벽돌
벽이 떨어지고 동물이 멈춰서 벽을 밉니다. 터미널에서 답하는 순간 벽이 내려갑니다.
알림이 아니라 **세션의 실제 트랜스크립트**를 따라가기 때문입니다.

**🖱️ 동물을 클릭하면 지금 어디까지 왔는지 보입니다.** 마우스를 올리고 누르면 어느
프로젝트인지, 무엇을 시켰는지, 마지막에 뭐라고 답했는지가 나옵니다. 벽에 막혀 있으면
*실제로* 묻고 있는 질문이나 허가를 기다리는 도구 호출(`Bash — git push …`)이 그대로
뜹니다. 벽돌도 클릭됩니다.

**🐾 메뉴 바가 곧 인원수입니다.** 상태 표시줄에 돌고 있는 세션마다 한 마리가 뜨고,
막힌 것은 벽을 앞세워 🧱🐕 처럼 섭니다. 메뉴에서 그 줄에 마우스를 올리면 러너를
클릭한 것과 같은 상세가 나옵니다.

**⏳ 높이 = Claude 한도가 리셋되기까지 남은 시간.** Claude 사용량 한도는 5시간
블록으로 갱신됩니다. 블록이 막 시작하면 러너가 화면 위쪽에서 달리고, 블록이 흘러갈수록
아래로 내려오며 흐려집니다. 바닥에서 달리고 있으면 마무리할 때라는 신호입니다.
메뉴 줄에 정확한 시간이 적히고, **실제로 측정되는 유일한 숫자**인 이 블록의 토큰 사용량도
같이 나옵니다.

> 이건 연료계가 아니라 **시계**입니다. 리셋이 얼마나 가까운지를 말할 뿐, 할당량을
> 얼마나 썼는지는 말하지 않습니다 — 로컬에 그걸 알려주는 정보가 없습니다. 예외가 하나
> 있습니다: Claude가 **직접** 한도 도달을 알려오면, 그때는 러너가 픽셀 아트 묘비로
> 얼어붙어 Claude가 알려준 리셋 시각까지 그대로 있습니다.

**🔔 소리는 고르는 겁니다.** "끝났을 때"와 "나를 부를 때"에 macOS 시스템 사운드를
각각 고르거나 끌 수 있습니다. 고르는 순간 미리 들립니다.

**💤 방해하지 않습니다.** 러너와 그 벽의 몇 픽셀을 빼면 오버레이 전체로 클릭이 그대로
통과하므로 작업 중인 앱을 가리지 않습니다. Dock 아이콘도 없습니다. **"동작 줄이기"**를
켜 두었다면 동물이 제자리에 서서 정보만 그대로 말합니다. 오버레이를 완전히 끄고 메뉴 바
표시만 남길 수도 있습니다. 메뉴에 **로그인 시 실행** 토글이 있습니다.

전부 손으로 그린 픽셀 스프라이트이고, 네 프레임짜리 진짜 보행 주기가 돕니다 —

## 어시스턴트별로 되는 것

VibeCheck은 각 CLI가 남기는 것만 읽습니다. 세 도구가 남기는 양이 다르므로 정직한 표를
둡니다.

| | Claude Code | Codex CLI | Gemini CLI |
|---|---|---|---|
| 세션마다 러너 | ✅ | ✅ | ✅ |
| API 응답 대기 중에도 "일하는 중"을 앎 | ✅ | ✅ | ⚠️ CPU만 |
| 🧱 벽 (나를 기다림) | ✅ | ✅ 승인 요청 | ❌ |
| 클릭 상세 (지시 / 답 / 대기 중인 호출) | ✅ | ✅ | ❌ |
| 높이 = 리셋까지 남은 시간 | ✅ | ❌ | ❌ |
| 훅으로 정확한 턴 경계 | ✅ | ❌ | ❌ |

**Gemini 칸이 빈 이유:** 나머지 둘은 읽을 수 있는 세션 기록을 남기므로, 프로세스가 CPU
0%로 API를 기다리는 동안에도 턴이 진행 중임을 알 수 있습니다. Gemini CLI는 그런 기록을
남기지 않아서 CPU만으로 판정합니다 — 즉 **기다리기만 하는** Gemini 세션이 끝난 것처럼
보일 수 있습니다. Gemini CLI가 턴을 어디에 기록하는지 아신다면, 아주 환영받을 작은 PR
입니다.

## 더 정확하게 (클릭 한 번)

기본 상태로도 VibeCheck은 알아서 판단합니다 — 설정이 필요 없습니다. 다만 *정확하게*
하고 싶다면 메뉴에서 **"Claude Code 훅 연동"** 을 켜세요.

그러면 VibeCheck이 추론하는 대신 Claude Code가 턴의 시작·끝·막힘을 직접 알려줍니다.
권한 프롬프트가 뜨는 순간 벽이 섭니다.

```bash
/Applications/VibeCheck.app/Contents/MacOS/VibeCheck --install-hooks     # 메뉴에서 해도 됩니다
/Applications/VibeCheck.app/Contents/MacOS/VibeCheck --uninstall-hooks
```

`~/.claude/settings.json`에 **병합**되고(먼저 백업합니다), 다른 설정과 남의 훅은 건드리지
않습니다. 끄면 VibeCheck이 넣은 것만 빠집니다.

Codex에는 같은 게 필요 없습니다. 롤아웃 로그에 `task_started` · `task_complete`가 이미
그대로 적히므로 설정 없이도 턴이 정확합니다.

## 있을 법한 질문

**컴퓨터가 느려지나요?** 네이티브 Swift 바이너리 하나입니다 — Electron도, 런타임도,
의존성도 없습니다. 초당 두 번 정도 libproc으로 프로세스 표를 읽고(서브프로세스를 띄우지
않습니다) 픽셀을 좀 그립니다. 트랜스크립트는 append-only라서 한 번만 읽고, 이후로는
지난번에 멈춘 지점부터만 읽습니다.

**어디로 보내나요?** 아니요. 이 앱에는 네트워크 코드가 아예 없습니다. 로컬 세션 파일을
읽는 것이 전부입니다.

**훅이 Claude를 느리게 하지 않나요?** 훅은 도는 동안 Claude를 붙잡으므로, VibeCheck은
턴 경계 이벤트만 등록하고(도구마다 걸지 않습니다) 훅은 약 10ms 만에 끝납니다.

**내 프롬프트가 화면에 뜨는데요.** 맞습니다 — 클릭 패널의 요점이 그것이고, 화면 공유나
녹화 전에 알아 둘 값어치가 있습니다. 밖으로 나가는 것은 없지만, 패널은 여러분이 친 것을
그대로 그립니다.

**뭔가 이상합니다.** `./build/VibeCheck --debug` 를 돌리면 폴링마다 각 세션을 어떻게
보고 있는지 찍힙니다. `--check-session <디렉터리>` 는 그 작업 디렉터리에 어떤 트랜스크립트를
골랐고 거기서 무엇을 읽었는지 보여주고, `--check-usage` 는 현재 5시간 블록을 찍습니다.

## 실제로 어떻게 동작하나

<details>
<summary>궁금한 분만 (클릭해서 펼치기)</summary>

VibeCheck은 1.5초마다 libproc으로 프로세스 표를 읽고 `claude` / `codex` / `gemini`
프로세스를 PID로 추적합니다 — 서브프로세스를 띄우지 않고, 전체 커맨드라인은 이름이
어시스턴트일 수 있는 소수의 프로세스에 대해서만 읽습니다. 대화형 터미널 세션만 셉니다:
상주 헬퍼(데몬, pty 호스트), 일회성 호출(`claude auth status`, `claude -p …`,
`codex exec …`), 진짜 Codex 바이너리를 띄우는 npm 셸, 다른 세션의 도구가 띄운 CLI는
전부 건너뜁니다. 그리고 새 pid는 두 번의 폴링을 살아남아야 화면에 나올 수 있습니다 —
개발 서버가 몇 초마다 `gemini auth status`를 부른다고 유령 러너가 쏟아지지 않도록.
작업 디렉터리는 libproc(`proc_pidinfo`)에서 옵니다.

CPU는 프로세스 트리가 **소비한 CPU 시간**을 폴링 사이의 차분으로 잽니다 — "지금 바쁜가"의
실제 의미가 그것입니다. 자식 프로세스까지 합산하므로 긴 빌드·테스트도 일로 셉니다.

**훅을 켜면** `SessionStart`, `UserPromptSubmit`, `Notification`, `Stop`,
`SessionEnd`가 각각 `VibeCheck --hook`을 실행해 그 세션의 상태를
`~/.vibecheck/sessions/` 에 기록합니다. 진짜 "너를 기다린다" 알림만 벽을 세웁니다 —
유휴 알림이나 완료 알림은 아닙니다. 훅 보고는 트랜스크립트가 동의하는 동안에만
신뢰됩니다: Esc로 턴을 끊으면 `Stop` 훅이 안 뜨므로 3분간 조용한 "working" 보고는
불신하고, 권한을 승인해도 훅이 안 뜨므로 트랜스크립트가 그 지점을 지나가는 순간
"attention" 보고를 버립니다. 훅은 세션의 진짜 id도 실어 나르므로 한 프로젝트에서 여러
세션이 돌 때 로그가 제 파일을 가리키고, **어느 어시스턴트가 보고했는지**도 실으므로
같은 폴더에서 도는 Codex 세션에 Claude 세션의 상태가 넘어가지 않습니다.

**훅이 없으면** 두 신호를 합칩니다:

1. **CPU**, 세션의 자식 프로세스까지 합산.
2. **트랜스크립트의 턴 상태.** 여기서 두 기록 형식이 갈립니다:
   - **Claude Code** — 마지막 항목의 `stop_reason`. 턴은 `end_turn`(또는
     `stop_sequence` / `max_tokens` / `refusal`)일 때만 끝납니다. `tool_use`는 더 올
     것이 있다는 뜻이라, 프로세스가 조용히 API를 기다리는 동안에도 "일하는 중"으로
     둡니다. 이게 생각보다 중요합니다: 어시스턴트 텍스트와 사고 블록도 **턴 중간에**
     기록되므로, 내용만 보고 판단하면 바쁜 세션이 턴당 수십 번 끝난 것으로 찍히고
     러너가 계속 뛰쳐나갔다 들어옵니다.
   - **Codex CLI** — `~/.codex/sessions/**/rollout-*.jsonl` 이 대놓고 말해 줍니다:
     `task_started`가 턴을 열고, `task_complete`·`turn_aborted`가 닫고,
     `*_approval_request`가 "너에게 막혀 있다"는 뜻입니다. 스캔은 뒤에서부터 올라가다
     처음 만난 결정적 이벤트에서 멈추므로, 이미 승인된 요청은 그 뒤에 찍힌 도구 출력에
     묻힙니다 — 그리고 끊임없이 쏟아지는 `token_count`는 진행으로 오해하지 않고
     건너뜁니다. 돌고 있는 세션과 롤아웃 파일은 `session_meta`에 적힌 작업 디렉터리로
     연결합니다.

클릭 패널의 상세도 트랜스크립트에서 옵니다: 가장 최근 어시스턴트 텍스트가 "마지막 응답"
이고, 로그 끝에 답이 없는 도구 호출이 있으면 그것이 기다리는 질문(Claude의
`AskUserQuestion`이면 질문 문장 자체)이거나, 허가를 기다리는 도구 호출이거나, Codex가
승인받으려는 명령입니다.

5시간 블록은 [ccusage](https://github.com/ryoppippi/ccusage)와 같은 방식으로 추정합니다
— 이전 블록이 끝난 뒤 첫 활동을 시각 단위로 내림하고 5시간을 더합니다. 서버의 실제
리셋과 몇 분 차이가 날 수 있습니다. 그리고 타이머가 아니라 **세션이 턴을 시작하는 순간**
다시 계산하므로, 러너가 낡은 블록을 기준으로 그려지는 일이 없습니다. 토큰 수에서는 캐시
**재읽기**를 뺍니다: 같은 캐시 프리픽스를 요청마다 다시 읽는 값이라, 넣으면 블록이 쓴
양이 아니라 대화가 얼마나 긴지를 재게 됩니다.

</details>

## 동물 추가하기

정말로 2분짜리 PR입니다. 스프라이트는 코드로 그립니다 — 여섯 가지 몸 틀 중 하나를 고르고,
팔레트와 알아볼 수 있는 특징을 주면 끝입니다. 전부
[`Sources/VibeCheck/Sprites.swift`](Sources/VibeCheck/Sprites.swift) 에 있습니다.

```swift
"🦔": Species(.small, body: (0.55, 0.42, 0.32), accent: (0.30, 0.24, 0.18), accessory: .spikes),
```

`./build/VibeCheck --dump-sprites out.png` 로 결과를 미리 봅니다.
